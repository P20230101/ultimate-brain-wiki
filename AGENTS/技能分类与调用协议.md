# Skill 分类与调用协议

本文件是 Second Brain 中 skill 的唯一路由规则。目标是让每项任务先确定工作阶段，再调用对应 skill；不因名称相近而重复调用或混用。

## 一、固定入口

每次开始任务必须按以下顺序执行：

1. 阅读根目录 `AGENTS.md`。
2. 阅读 `index.md`，确定资料、Wiki、schema 或环境配置的目标位置。
3. 判断任务类型，只选择一个主 skill；只有主 skill 明确需要时才选择辅助 skill。
4. 涉及外部资料时，先把来源放入 `raw/`，再编译到 `wiki/`。
5. 完成后按任务类型执行验证，并在 `log.md` 追加记录。

## 二、分类清单

### 1. 流程控制与质量验证

| Skill | 角色 | 何时调用 |
| --- | --- | --- |
| `superpowers:using-superpowers` | 总入口 | 每次任务开始时确认适用 skill |
| `superpowers:brainstorming` | 需求澄清 | 新功能、创意方案或行为改变之前 |
| `superpowers:writing-plans` | 实施计划 | 多步骤工程任务且已有明确需求时 |
| `superpowers:systematic-debugging` | 根因分析 | 出现错误、失败或异常行为时 |
| `superpowers:test-driven-development` | 测试驱动 | 修改代码功能或修复可自动测试的问题时 |
| `superpowers:verification-before-completion` | 交付验收 | 任何声称完成、通过或修复之前 |
| `superpowers:requesting-code-review` | 代码复核 | 重要代码变更完成后需要审查时 |

这些 skill 规定工作顺序，不负责解析论文或代替领域 skill。出现异常时先用 `systematic-debugging`，不能直接叠加修补。

### 2. 论文、PDF 与资料解析

| Skill | 角色 | 调用顺序 |
| --- | --- | --- |
| `mineru` | 论文/PDF/图片/Office 主解析器 | 读取、OCR、表格、公式、分页和定位引用时优先调用 |
| `pdf:pdf` | PDF 视觉检查与生成 | 需要渲染页面、检查版式、表单或生成 PDF 时调用 |
| `documents:documents` | Word 文档 | 读取、编辑、批注或生成 DOCX 时调用 |
| `markdown-converter` | 格式转换 | MinerU 不支持或用户明确要求转换时调用 |
| `paper-analyzer` | 论文深度分析 | 已获得解析文本后，提取方法、结果、图表和代码信息时调用 |

规则：支持的论文资料先用 `mineru`，不能先用通用 PDF 解析器；`pdf:pdf` 负责版式证据，不代替 MinerU 的论文内容解析。

### 3. 文献检索与学术证据

| 工具或 Skill | 角色 | 调用方式 |
| --- | --- | --- |
| Semantic Scholar API | 文献检索和元数据 | 使用 `S2_API_KEY`，查询题名、作者、年份、摘要和论文 ID |
| `paper-analyzer` | 文献内容分析 | 对已获取的论文进行结构化提取 |
| `NovaForge` | 科研笔记编译 | 将论文证据编译为问题、方法、结果、局限和行动项 |
| `web` | 官方来源核对 | 需要最新信息、原始链接或精确出处时使用 |

文献流程固定为：检索元数据 -> 获取原始资料 -> `mineru` 解析 -> `paper-analyzer` 分析 -> `NovaForge` 编译 -> 写入 `raw/` 和 `wiki/`。

### 4. 论文写作、润色与审阅

| 资源 | 角色 |
| --- | --- |
| `AGENTS/论文写作框架.md` | 本库的论文写作总规范 |
| `NovaForge` | 论文结构、科研笔记和章节编译 |
| `paper-analyzer` | 从原始论文提取可引用证据 |
| `superpowers:verification-before-completion` | 检查事实、来源、数据和输出完整性 |

论文写作顺序固定为：阅读论文写作框架 -> 明确研究问题和证据范围 -> 必要时检索并解析文献 -> 按 Introduction 倒三角和 Discussion 正三角组织 -> 检查 Figure/Table、数据、引用和局限 -> 输出 Markdown -> 记录日志。

### 5. 数据、实验与可视化

| Skill | 角色 | 何时调用 |
| --- | --- | --- |
| `spreadsheets:Spreadsheets` | 表格分析与生成 | XLSX、XLS、CSV、TSV 的公式、统计、图表和文件处理 |
| `spreadsheets:excel-live-control` | 当前打开的 Excel | 用户明确要求操作正在打开的 Excel 时 |
| `visualize:visualize` | 图表、模拟和交互可视化 | 需要解释趋势、比较结果或制作科学图表时 |
| `NovaForge` | 实验记录编译 | 记录变量、样本、方法、结果、误差、限制和复现步骤时 |

数据流程固定为：原始数据进入 `raw/` -> 确认样本和变量 -> 使用表格工具或现有脚本处理 -> 使用 `visualize` 展示 -> 将处理报告和证据写入 `wiki/` 或实验目录 -> 验证数值和文件路径。

### 6. 图表、演示与视觉材料

| Skill | 角色 | 何时调用 |
| --- | --- | --- |
| `presentations:Presentations` | 创建或编辑 PPTX/Slides | 需要交付演示文稿文件时 |
| `ppt-visual` | 设计幻灯片视觉结构 | 需要布局、图形或视觉叙事时，作为 PPT 主 skill 的辅助 |
| `imagegen` | 生成或编辑位图 | 只有确实需要 AI 位图素材时调用 |
| `paper-comic` | 论文教育漫画 | 用户明确要求论文漫画时调用 |

演示流程固定为：确定论文证据 -> 必要时用 `mineru` 解析 -> `presentations` 负责文件 -> `ppt-visual` 负责视觉方案 -> 渲染检查 -> 交付。不得用 `imagegen` 代替数据图表或实验结果图。

### 7. 环境、Skill 与桌面操作

| Skill | 角色 | 边界 |
| --- | --- | --- |
| `skill-installer` | 列出和安装 skill | 只有用户要求安装、升级或盘点 skill 时调用 |
| `find-skills` | 发现可用能力 | 不确定是否已有合适 skill 时调用 |
| `openai-docs` | OpenAI/Codex 官方说明 | 查询 Codex、OpenAI API、skill 或环境行为时调用 |
| `skill-creator` | 创建或更新 skill | 只有用户要求新建 skill 时调用 |
| `plugin-creator` | 创建 Codex 插件 | 只有用户要求插件结构时调用 |
| `Desktop Control` / `computer-use:computer-use` | 原生桌面 UI | 只有 CLI、API 或文件接口无法完成且确实需要 UI 时调用 |

环境维护顺序固定为：检测版本和路径 -> 确认安装归属 -> 只改根因 -> 验证命令和运行状态 -> 更新本文件或科研工具环境记录。不能用桌面操作替代已有 CLI/API。

## 三、用户目标到 Skill 的路由

| 用户表达 | 主 skill | 必要辅助 |
| --- | --- | --- |
| “读这篇论文/提取表格公式” | `mineru` | `paper-analyzer`、`pdf:pdf`（版式问题） |
| “找相关文献/找同物种研究” | Semantic Scholar API | `web`、`paper-analyzer` |
| “总结论文并放进 Wiki” | `paper-analyzer` | `mineru`、`NovaForge` |
| “润色论文/写 Introduction 或 Discussion” | `NovaForge` | `AGENTS/论文写作框架.md`、文献证据 |
| “分析 CSV/Excel 实验数据” | `spreadsheets:Spreadsheets` | `visualize`、`NovaForge` |
| “做论文 PPT” | `presentations:Presentations` | `ppt-visual`、`mineru` |
| “检查 PDF 版式” | `pdf:pdf` | `verification-before-completion` |
| “安装或盘点 skill” | `skill-installer` | `find-skills`、`verification-before-completion` |
| “环境报错/命令失败” | `superpowers:systematic-debugging` | 对应领域 skill |

## 五、每次交付前的最小检查

- 主 skill 与任务类型一致。
- 所有输入资料和输出页面位于当前 Second Brain。
- 重要结论有来源、证据或“工作假设”标记。
- 解析、数据、链接、引用或版式检查已经实际运行。
- `log.md` 已追加本次操作和待验证项。
- 未把 API key、访问令牌或本机密钥写入 vault、日志或 Git。

## 六、当前环境清单

### 用户级已安装且可用

`mineru`、`paper-analyzer`、`NovaForge`、`paper-comic`、`ppt-visual`、`markdown-converter`、`find-skills`、`desktop-control`，以及 `superpowers` 下的流程 skill。

### 系统或 bundled 可用

`skill-installer`、`openai-docs`、`skill-creator`、`plugin-creator`、`imagegen`、`computer-use`、`documents`、`pdf`、`presentations`、`spreadsheets`、`excel-live-control`、`template-creator`、`visualize`。

### 目录存在但不可用

`baoyu-gemini-web` 当前目录为空，没有 `SKILL.md`，不能调用，也不视为已安装。除非找到明确的公开仓库路径，否则不自动补装。

### 调用边界

- 先选一个主 skill，再按主 skill 的明确依赖调用辅助 skill。
- `mineru`、`markdown-converter`、`pdf:pdf` 不能因为都能处理 PDF 就同时默认调用；论文内容用 `mineru`，版式用 `pdf:pdf`，纯格式转换才用 `markdown-converter`。
- `presentations` 负责 PPT 文件，`ppt-visual` 只负责视觉方案；不能用 `imagegen` 代替实验图表。
- `spreadsheets` 负责表格文件，`excel-live-control` 只用于当前打开的 Excel；两者不能混用同一输入流程。
- 出现异常先调用 `systematic-debugging`，修复后再调用 `verification-before-completion`，不能跳过根因分析。

### 力学方向适配规则

将其视为流程设计参考，不作为现成模型直接调用。若后续创建力学版适配器，应保留“原始资料校验—阶段性输出—人工确认—结果回读”的流程控制，并将变量和约束替换为：载荷、位移、应力、应变、材料参数、边界条件、初始条件、坐标系、单位制、网格/时间步长、收敛准则、测量误差、模型校准与独立验证。任何力学结论必须来自真实实验数据、仿真输出或文献定位，不得由经济学模块中的“预期系数方向”“因果反馈”或政策建议规则推演。

### 当前路由

- 文献获取与 PDF/图表/公式解析：`mineru`。
- 文献结构化编译：`paper-analyzer` 的本地证据整理原则 + `NovaForge` 科研模式，但输出位置仍遵守本库的 `raw/`、`wiki/`、`schema/` 结构。
- 力学数据与实验结果：根据文件类型选择 `spreadsheets:Spreadsheets`、`visualize:visualize` 或专用分析脚本；先记录单位、样本、误差和边界条件。
