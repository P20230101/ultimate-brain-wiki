# 论文写作框架

本文件是长期写入 Obsidian Second Brain 的论文写作协议。凡是任务涉及论文润色、Discussion 写作、实验结果讨论、文献对照、论文精读或论文结构化总结，优先按本框架执行。

## 1. 需求澄清协议

在给出方案、改写文本或正式输出前，先向用户提问。

- 一次只问一个问题。
- 根据用户回答继续追问。
- 直到对用户的真实需求、目标、文本用途、学科背景、目标期刊或评价标准达到约 95% 信心，再开始给出方案或正式文本。
- 如果用户明确要求立即执行，可以先说明当前假设，再在假设范围内完成最小必要输出。

优先澄清的问题包括：

- 文本用于论文的哪个部分：摘要、引言、方法、结果、讨论、结论或回复审稿人。
- 目标语言和风格：中文学术、英文 SCI、基金申请、毕业论文或综述。
- 是否需要保留原意、压缩篇幅、增强逻辑、增加文献支撑或重构段落。
- 是否已有目标期刊、字数限制、参考文献格式和图表编号。

## 2. 学术润色规则

作为资深论文润色专家处理文本时，遵守以下规则：

1. 使用正式、专业和学术化的词汇，避免非正式、日常化或口语化表达。
2. 在论证需要支撑时，尽量引用相关研究或文献；若无法确认具体文献，不编造引用，应标记为需要补充文献。
3. 使用客观、中立的语言，避免过度主观或情绪化判断。
4. 保证文本结构清晰，段落划分明确，每个段落有清楚的中心思想。
5. 使用必要的过渡词和衔接表达，例如“此外”“根据”“因此”“相较而言”“与此同时”，增强逻辑连贯性。
6. 删除重复、冗余或不服务于论证目标的信息，确保每一句话都为整体内容增加价值。
7. 可在合适位置使用被动语态以增强正式性，但避免过度使用导致句子僵硬。
8. 检查文本中的数据、事实和术语，无法验证时明确标记为“待核实”，不静默默认其正确。
9. 尽量保持作者原始结论和研究边界，不扩大研究贡献，不制造未被数据支持的因果关系。

## 3. Discussion 写作思路

Discussion 的核心目标是解释结果、证明结论、连接文献并说明边界。优先按“自证、旁征、博引”三层展开。

### 3.1 自证

自证是用本研究自己的指标体系和实验数据证明实验结论的正确性。

写作重点：

- 用核心指标直接回应研究假设。
- 说明不同小实验之间的逻辑关系和相互支撑关系。
- 通过多个结果之间的关联，反复推敲并证明结论是否成立。
- 在实验设计阶段注意指标的针对性和具体性，避免指标过宽导致讨论无法落到结论。

常用表达：

- “本研究结果显示……，该结果与……指标的变化趋势一致，提示……”
- “进一步结合……实验结果，可以支持……这一判断。”
- “上述结果从……和……两个层面共同表明……”

### 3.2 旁征

旁征是引用同行研究中的类似结果，为本研究结论提供外部支持。

写作重点：

- 优先筛选与本研究主题相近的文献。
- 优先选择同一物种、相近生理阶段、相近处理条件或相近实验平台下的研究。
- 不只罗列文献结论，要说明其与本研究结果之间的对应关系。

常用表达：

- “类似地，已有研究在……中观察到……，这与本研究中……的变化趋势一致。”
- “该结果与……关于……的报道相互印证。”
- “这些一致性结果表明，……可能具有较好的稳定性或普遍性。”

### 3.3 博引

博引是寻找与本研究结果不同或部分不同的文献，通过差异分析进一步强化本研究结论的解释力。

写作重点：

- 优先选择同一研究问题在不同物种、不同生理阶段、不同处理条件或不同实验体系中的结果。
- 不把差异简单写成矛盾，而要解释差异可能来自物种、发育阶段、样本来源、处理强度、检测方法或统计模型。
- 通过差异讨论明确本研究结论的适用边界。

常用表达：

- “然而，部分研究在……中报道了不同结果。这种差异可能与……有关。”
- “与……不同，本研究聚焦于……，因此结果差异可能反映了……”
- “这种差异并不否定本研究结果，而是提示……可能受到……条件调控。”

## 4. 论文结构化总结框架

对论文、草稿或研究材料进行总结时，按以下结构输出 Markdown。

```md
# 论文总结：标题

## 1. 核心科学问题

清晰阐述本研究旨在解决的核心科学问题。

## 2. 研究设计

概述整体研究思路，包括研究对象、对照关系、实验逻辑和主要验证路径。

## 3. 数据/样本来源

说明数据获取方式、样本规模、样本分组、选择标准与样本特征。

## 4. 方法与技术

详述所使用的关键技术、算法、模型、实验平台、试剂材料或软件工具。

## 5. 分析流程

分步说明整体研究方案中的实验步骤、数据处理流程、统计分析方法或理论推导关键环节。

## 6. 核心发现

提炼研究中最重要、最创新的科学发现或观测现象，并归纳作者基于证据得出的最终结论。

## 7. 实验结果

总结关键定量结果和定性结论。必要时按实验模块分条列出。

## 8. Figure 与 Table 索引

| 编号 | 标题 | 核心内容 | 可用于支撑的结论 |
| --- | --- | --- | --- |
| Figure 1 |  |  |  |
| Table 1 |  |  |  |

## 9. 待核实信息

- 数据或事实：
- 引文：
- 术语：
- 图表编号：
```

## 5. 输出约定

- 默认使用中文输出。
- 用户提供原文时，先保留核心意思，再提升学术性、逻辑性和结构清晰度。
- 用户要求“润色”时，优先给出润色后版本；如有必要，再给出关键修改说明。
- 用户要求“讨论”时，按“自证、旁征、博引”组织论证。
- 用户要求“总结论文”时，按第 4 节 Markdown 框架输出。
- 遇到事实、数据、文献或图表无法确认的情况，明确标记为“待核实”，不编造。
